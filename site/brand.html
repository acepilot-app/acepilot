AcePilot Brand

How AcePilot looks, sounds, and presents itself. Every decision here serves one goal: fastest path from "I found this" to "I installed this."

Logo

A geometric "A" mark — two strokes meeting at an apex, joined by a crossbar. Sharp, minimal, scalable to any size.

  • Use the icon + wordmark together in nav, headers, and email
  • Use the icon alone as favicon, app icon, or avatar (≥16px)
  • Use accent purple (#6c5ce7) for the mark on all backgrounds
  • Maintain clear space equal to the icon height on all sides
  • Don't recolor the mark (no gradients, no white fill on dark bg)
  • Don't stretch or rotate the mark
  • Don't use the wordmark without the icon in primary placements
  • Don't place on low-contrast backgrounds that compromise legibility

Category definition

AcePilot is not an AI assistant. It's not a code editor. It's autonomous execution infrastructure for Claude Code — the layer between "I have a goal" and "here's the PR."

Tone of voice

Five principles. Every piece of copy passes all five.

01
Direct

State what it does. No wind-up. "Get a PR" beats "facilitate the creation of pull requests."

02
Confident

No hedging. "The product team you never hired" — not "a tool that might help teams."

03
Technical

Use the right words. Developers respect precision. Never dumb down.

04
Outcome-first

Lead with what happens. "6 done, 1 concern, 0 blocked. PR: ..." — not how it works internally.

05
No buzzwords

Never: "revolutionary," "game-changing," "AI-powered magic," "supercharge." These are red flags.

Copy rules

Specific patterns to follow and avoid.

✓ Write this
"Give it a goal. Get a PR."
✕ Not this
"Let AcePilot supercharge your development workflow with AI."
✓ Write this
"6 specialist agents review everything you ship."
✕ Not this
"Our revolutionary multi-agent AI system provides comprehensive code review coverage."
✓ Write this
"7 config files. 30 seconds to install. No dependencies."
✕ Not this
"A lightweight, frictionless onboarding experience designed for developer productivity."
✓ Write this
"Not a fork. Not a wrapper. Config files."
✕ Not this
"AcePilot is a native integration that seamlessly enhances your Claude Code experience."

Do's & Don'ts

Across all brand touchpoints.

Do
  • Lead with outcomes, follow with mechanism
  • Show the product working (terminal output, not screenshots of docs)
  • Quantify when possible: "~62% reduction" beats "significant improvement"
  • Use monospace for all command-line references
  • Name the experts behind the agents (Nielsen, Schneier, Souders)
  • Keep CTAs to one per section, verb-led ("Install free", "View on GitHub")
Don't
  • Use passive voice ("is designed to") — use active ("does")
  • Describe feelings ("elegant", "beautiful", "delightful") — describe results
  • Add exclamation marks to technical copy
  • Use we/our where possible — prefer "AcePilot" or second-person "you"
  • Place version numbers in hero/badge positions — use benefit-led labels
  • Introduce new colors outside the palette without updating this guide
