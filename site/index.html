What changes

What happens when you type /acepilot

Claude Code absorbs your project, makes autonomous business decisions, and shifts into a different operating mode. Same tool, different brain.

Project scanning

Reads your codebase, README, build output, TODOs, and specs. Returns a prioritized task list scored by impact, urgency, and confidence.

Confidence gate

Two-way door → execute immediately. Higher stakes → show plan, proceed. One-way door → stop, present options. Reversibility-based, never over-commits.

Self-validation

Build, lint, test after every change. Then a separate qualify step: did the code solve the right problem? Two independent checks, not one.

Context survival

12 state files track tasks, decisions, knowledge, identity, and mode. Survives compaction, model switches, and session crashes. Resumes where it left off.

Circuit breaker

3 consecutive failures → stop. Same error 3 times → stop. Same file edited 3 times in one task → stop. Enters recovery mode, breaks the problem down, retries.

Git checkpoints

Commits after each verified task. Every checkpoint is a buildable state. Stashes dirty trees on start, restores on finish. Feature branches enforced.

How it works

Not a fork. Not a wrapper. Config files.

AcePilot installs into Claude Code's native config structure. No runtime, no daemon, no API keys. It's the same Claude Code you already use — configured to operate differently.

~/.claude/

User-level files

CLAUDE.md (trigger), settings.json (permissions + status line), commands/acepilot.md (the brain), 6 agent files (researcher, reviewer, designer, security, architect, strategist).

.claude/

Project-level files

settings.json (hooks for code formatting and compaction survival), rules/browser.md (UI verification). Applied per-project.

.claude/state/

Runtime state

12 flat files. TASKS, DECISIONS, KNOWLEDGE, IDENTITY, ANALYTICS, PATTERNS, USER-KNOWLEDGE, CONTEXT, METRICS, MODE, CIRCUIT, STASH_REF. All plain text. All git-trackable.
